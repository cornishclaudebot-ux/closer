how it works

The stack, and why each piece is there.

Next.js on Vercel is the app. Supabase is everything stateful. n8n is the async glue. No piece is there for fashion.

who
GCU student

Opens Closer on their phone, shares location while on campus.

browser · PWA
the app
Next.js on Vercel

UI, server actions, and API routes. Ships on every push with its own preview URL.

next.js · vercel edge
the backend
Supabase

Auth, Postgres + PostGIS, Realtime, and Storage. One service, row-level secured.

postgres · postgis · realtime
the glue
n8n

Polls new signups and events, routes them to the CRM, safety review, and digests.

self-hosted · scheduled
01 · identity

Real students only

GCU Microsoft (Entra ID) sign-in, so every profile is a verified classmate, not a bot or a stranger three cities over.

Supabase Auth · Entra
02 · the core

The proximity engine

Coarse layer: GPS + geofence pings become geo-points, and PostGIS answers "who did I cross paths with, and how often." Never where. The fine ~20 ft layer is Bluetooth LE / UWB in V2.

PostGIS · BLE (v2)
03 · live

Matches and presence

A mutual like fires instantly, and "you're both here now" appears while it still matters. No refresh.

Supabase Realtime
04 · safety

Yours by default

Row Level Security means a student only ever reads what they're allowed to. Photos live in private Storage buckets.

RLS + Storage
05 · ship speed

Preview every change

Every edit gets a live Vercel URL to test on a real phone before it's real for anyone else.

Vercel
06 · off-app work

Runs without you

New signups route to the CRM, flagged reports reach you, and a weekly "who you missed" digest goes out. All in n8n.
